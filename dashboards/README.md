# Power BI & Visual Analytics Specification — Spotify Lakehouse

This directory contains the specifications, DAX measure definitions, Star Schema semantic models, and reporting layouts for the Gold-layer BI reporting suite.

The reporting architecture serves two distinct audiences:
1. **Executive & Product Analytics:** Modern Power BI dashboards addressing core business questions (Peak usage & capacity, Subscription conversion propensity, Content market share, and Pipeline Data Quality audit).
2. **Consumer Engagement ("Spotify Wrapped"):** A nostalgic, interactive cassette-themed visual experience styled after the curated `Mixtape_Wrapped_storyboard.html`.

---

## 1. Connectivity & Data Sourcing

- **Engine:** Power BI VertiPaq (Import mode).
- **Direct Lakehouse Connection:**
  - Connector: *Azure Databricks*
  - Hostname: `<workspace-url>.azuredatabricks.net`
  - HTTP Path: `/sql/1.0/warehouses/<warehouse-id>`
  - Authentication: Personal Access Token (PAT) entered dynamically at connection time (never committed or embedded in `.pbix`).
  - Target Schema: `gold` exclusively (Power BI **never** reads Bronze or Silver).
- **Fallback / Offline Serving Mode:**
  - If a live SQL Warehouse is unavailable, the model imports the export files generated by `40_serving_export` from `<landing_root>/serving/parquet/` or `csv/`.

## 2. Star Schema Semantic Model Architecture

The semantic layer faithfully reflects the Lakehouse Star Schema with **strict single-direction, one-to-many relationships**.

```
                +-----------------+
                |   dim_date      |
                |  (date_key PK)  |
                +--------+--------+
                         | 1
                         | 
                         | *
+-----------------+      |      +-----------------+
|   dim_user      |      |      |   dim_track     |
|  (user_sk PK)   |      |      |  (track_sk PK)  |
+--------+--------+      |      +--------+--------+
         | 1             |               | 1
         |               |               |
         | *             |               | *
    +----+---------------+---------------+----+
    |             fact_listening              |
    | (FKs: user_sk, track_sk, device_sk,    |
    |       date_key, hour_of_day)            |
    +----+---------------+---------------+----+
         | *                             | *
         |                               |
         | 1                             | 1
+--------+--------+             +--------+--------+
|   dim_device    |             |    dim_time     |
| (device_sk PK)  |             | (hour_of_day PK)|
+-----------------+             +-----------------+
```

### Model Configuration Rules:
1. **Surrogate Key Joins:** All dimension relationships terminate on Surrogate Keys (`_sk`). The join to `dim_user` connects `fact_listening[user_sk]` $\rightarrow$ `dim_user[user_sk]`, ensuring point-in-time accuracy for Slowly Changing Dimensions (SCD Type 2).
2. **Surrogate Key Visibility:** All `*_sk` surrogate key fields and internal `_row_hash` columns are marked **Hidden from Report View**.
3. **Date Table Configuration:** `dim_date` is explicitly marked as the official **Date Table** evaluated on the `dim_date[date]` column.
4. **Standalone Marts:** Flat marts (`gold.wrapped_user_year`, `gold.subscription_propensity_segments`, `gold.audit_quality_summary`) can operate standalone for specialized single-page views.

## 3. Core DAX Measures Catalog

All business calculations are centralized into a dedicated `_Measures` table:

```dax
// 1. Listening Volume Measures
Total Minutes = 
SUM('fact_listening'[minutes_played])

Total Hours = 
DIVIDE([Total Minutes], 60, 0)

Total Plays = 
SUM('fact_listening'[play_count])

Active Listeners = 
DISTINCTCOUNT('dim_user'[user_id])

Average Daily Minutes Per User = 
DIVIDE(
    [Total Minutes],
    CALCULATE(DISTINCTCOUNT('fact_listening'[date_key]) * [Active Listeners]),
    0
)

// 2. Behavioral & Engagement Measures
Skip Rate = 
AVERAGE('fact_listening'[is_skipped])

// Play-weighted average of the mart's pre-computed 60-day discovery_rate.
// subscription_propensity_segments.discovery_rate is the authoritative per-user
// value (NOT EXISTS / LAG lookback); weighting by total_plays avoids inflating
// light users who happen to listen exclusively to new tracks.
Discovery Rate = 
DIVIDE(
    SUMX(
        'subscription_propensity_segments',
        'subscription_propensity_segments'[discovery_rate]
            * 'subscription_propensity_segments'[total_plays]
    ),
    SUM('subscription_propensity_segments'[total_plays]),
    0
)

Completion Rate = 
AVERAGE('fact_listening'[completion_rate])

// 3. Subscription Propensity Measures
High Propensity Free Listeners = 
CALCULATE(
    COUNTROWS('subscription_propensity_segments'),
    'subscription_propensity_segments'[is_high_conversion_propensity] = TRUE()
)

Conversion Opportunity Rate = 
DIVIDE(
    [High Propensity Free Listeners],
    CALCULATE(COUNTROWS('subscription_propensity_segments'), 'subscription_propensity_segments'[is_premium] = FALSE()),
    0
)

// 4. Data Quality & Quarantine Measures
Total Quarantined Records = 
SUM('audit_quality_summary'[quarantined_records])

Total Ingested Records = 
SUM('audit_quality_summary'[total_ingested_records])

Lakehouse Quarantine Rate = 
DIVIDE([Total Quarantined Records], [Total Ingested Records], 0)

// 5. Revenue & Churn Risk Measures
// Revenue at risk = estimated MRR from High-Propensity Free users who haven't
// converted yet, valued at the standard $9.99/mo Premium price.
Revenue At Risk (MRR) = 
[High Propensity Free Listeners] * 9.99

// Churn-risk users = premium subscribers whose engagement_score has dropped
// below the Medium tier threshold in the current snapshot.
Churn-Risk Users = 
CALCULATE(
    COUNTROWS('subscription_propensity_segments'),
    'subscription_propensity_segments'[is_premium] = TRUE(),
    'subscription_propensity_segments'[tier] = "Low"
)

// 6. Stickiness & Activity Measures
// DAU = distinct users with at least one play on the selected date filter.
DAU = 
CALCULATE(
    DISTINCTCOUNT('fact_listening'[user_sk]),
    USERELATIONSHIP('dim_date'[date_key], 'fact_listening'[date_key])
)

// MAU = distinct users with at least one play within the current calendar month.
MAU = 
CALCULATE(
    DISTINCTCOUNT('fact_listening'[user_sk]),
    DATESINPERIOD('dim_date'[date], LASTDATE('dim_date'[date]), -30, DAY)
)

// Stickiness = DAU / MAU; industry benchmark is ~20 % for music streaming.
Stickiness = 
DIVIDE([DAU], [MAU], 0)

// Peak-to-average ratio: ratio of the busiest hour's play count to the
// hourly average — used for server capacity headroom planning.
Peak-to-Average Ratio = 
VAR _HourlyPlays = SUMMARIZE(
    'fact_listening',
    'dim_time'[hour_of_day],
    "hp", SUM('fact_listening'[play_count])
)
VAR _Peak = MAXX(_HourlyPlays, [hp])
VAR _Avg  = AVERAGEX(_HourlyPlays, [hp])
RETURN DIVIDE(_Peak, _Avg, 0)

// 7. Pipeline Operations Measures
// Hours Since Last Load: time elapsed since the most recent successful Gold commit.
Hours Since Last Load = 
DIVIDE(
    NOW() - MAX('audit_freshness'[latest_load_timestamp]),
    1/24,
    BLANK()
)

// Cost Per Run ($USD): converts the median Gold run duration to an estimated
// Databricks Serverless cost using the configured DBU rate and cluster size.
// Formula: (duration_p50_sec / 3600) * 1.5 DBU/hr * $0.15/DBU
Cost Per Run ($) = 
DIVIDE(
    AVERAGE('audit_pipeline_runs'[duration_p50]) / 3600 * 1.5 * 0.15,
    1,
    0
)
```

## 4. Dashboard Report Layouts (5 Pages)

### Page 1: Peak Usage & Platform Capacity (Business Question 1)
- **Objective:** Identify platform concurrency surges and listening habits by local hour vs. UTC for infrastructure capacity planning.
- **Visuals:**
  1. **Primary Matrix Heatmap:** Rows: `dim_date[day_name]`, Columns: `dim_time[hour_label]`, Values: `[Total Plays]`, conditional formatting with a red-to-green energy scale.
  2. **Local vs. UTC Comparison Clustered Column:** Displays play volume across 24 hours comparing listener local time against server UTC time.
  3. **Device Mix Donut Chart:** Listening volume proportion across `dim_device[device_category]` (Mobile, Desktop, Web, Smart Speaker).
  4. **Slicers:** Country, Subscription Tier (`is_premium`), Day Type (`is_weekend`).

### Page 2: Subscription Propensity & Conversion Funnel (Business Question 2)
- **Objective:** Segment Free listeners exhibiting heavy, diverse listening behavior similar to Premium subscribers.
- **Visuals:**
  1. **Propensity Distribution Clustered Bar:** `propensity_tier` (`High`, `Medium`, `Low`) split by `is_premium` (Free vs. Premium). The high-engagement Free cohort highlighted in Spotify green (`#1DB954`).
  2. **Conversion Opportunity Cards:** Total High-Propensity Free Users, Potential Annual Recurring Revenue ($9.99/mo per converted listener), Average Free Engagement Score.
  3. **Feature Correlation Scatter Plot:** X-axis: `volume_norm`, Y-axis: `device_diversity`, Bubble size: `total_minutes`, Color: `propensity_tier`.
  4. **Targeted User List Table:** `user_id`, `country`, `engagement_score`, `total_minutes`, `skip_rate`, `device_diversity`.

### Page 3: Content Performance & Market Share Trends (Business Question 3)
- **Objective:** Track rising and declining genres and artists month-over-month.
- **Visuals:**
  1. **Genre Market Share Area Chart:** 100% stacked area chart tracking monthly market share across top music genres (`rock`, `indie-alt`, `punjabi`, `jpop`, `hip-hop`).
  2. **Top Movers Matrix Table:** Top artists with columns for `monthly_minutes`, `genre_market_share`, and `mom_delta` (with dynamic green up-arrow / red down-arrow indicators).
  3. **Catalog Audio Feature Radar Chart:** Danceability, energy, valence, and tempo across selected genres.

### Page 4: "Spotify Wrapped" Storyboard Experience
- **Objective:** Consumer-facing personalized annual recap, aligned with the mixtape aesthetic in `Mixtape_Wrapped_storyboard.html`.
- **Aesthetic:** Retro analog cassette vibe (cream paper `#e8e6df`, deep black ink `#0e0e0e`, cassette red `#ff3b1f`, highlighter yellow `#ffe14a`).
- **Visual Elements (Driven by `gold.wrapped_user_year`):**
  1. **User Persona Slicer:** Instant switching between real listeners (`user_real_01`, `user_real_02`, `user_real_03`) and synthetic listeners.
  2. **Cassette Header Card:** Vintage tape graphic displaying "SIDE A: 2026" and listener username.
  3. **Odometer Minute Counter:** Prominent KPI card displaying `total_minutes` played and days equivalent.
  4. **Top 5 Artists & Top 5 Tracks "Receipt Card":** Styled table displaying ranked tracks, artists, and play minutes with album artwork thumbnails.
  5. **Listening Dial / Persona Badge:** Visual clock display highlighting listener peak hour and archetype (`Night Owl`, `Golden Hour Regular`, `Early Bird`).
  6. **Interactive Storyboard Integration:** Link / HTML visual embedding `Mixtape_Wrapped_storyboard.html` allowing users to click through animated story slides (quiz, artist race, vinyl genre platter).

### Page 5: Lakehouse Operations, Health & Quality Audit
- **Objective:** Demonstrate end-to-end data pipeline observability, execution durations, and data hygiene.
- **Visuals:**
  1. **Run Duration Line Chart:** Execution duration (`duration_sec`) by pipeline layer (`BRONZE_TO_SILVER`, `SILVER_TO_GOLD`) over time.
  2. **Data Pipeline Freshness Gauges:** Max `_partition_dt` and last successful `load_timestamp` across Bronze, Silver, and Gold.
  3. **Data Quality Quarantine Breakdown Bar Chart:** Quarantined record counts categorized by `rule_or_reason` (e.g. `INVALID_TIMESTAMP`, `NEGATIVE_PLAY_TIME`).
  4. **Idempotent Commit Status Matrix:** Historical run status (`SUCCESS`, `SKIPPED_UNCHANGED`, `FAILURE`) and rows mutated.
